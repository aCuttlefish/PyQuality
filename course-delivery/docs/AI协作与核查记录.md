# PyQuality AI 协作与核查记录

## 人机职责

| 阶段 | AI 参与 | 人或程序负责的核查 |
| --- | --- | --- |
| 需求澄清与规格 | 产品通过多轮追问（`/api/acceptance/clarify`）帮助用户补全排序、边界与输入域假设，再辅助提取需求与测试用例草案。Codex/Antigravity 协助准备课程规格稿与架构迭代。 | 用户逐项回答追问、对照原需求核对输入与预期并显式勾选锁定标准（`spec_hash` / `plan_hash`）；交付文档中的指标均与自动化测试及实跑报告一致。 |
| 代码生成和修复 | 真实模型实验中，DeepSeek 按提示词生成候选代码；验收失败时可由 `/api/acceptance/repair` 基于失败反例与已通过用例生成修复候选。 | 修复候选只标记为 `UNVALIDATED`，强制通过语法编译并送入 Docker 容器沿用同一锁死标准重跑验收，严禁模型自报通过。 |
| 判定和修改建议 | 模型可解释反例、提出修改方向或提示词改写。 | 程序按标准和执行证据判定（`verdict.py` 不问模型），后端硬填入输入/期望/实际观察值，通过结论限定在本轮已验收范围。 |
| 汇报与材料 | 组长在 Codex 与 Antigravity 对话中提出结构、通俗化表达、实机流程与演示要求，AI 协助重构 PPT、口播稿与代码迭代。 | 讲稿中的通过数、反例与测试数量均取自真实运行结果与 `pytest` 实测；终期演示视频由组长基于实机录制并放入 `course-delivery/demo.mp4`。 |
